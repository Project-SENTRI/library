# Contributing Guidelines

Thank you for taking the time to contribute! 

Whether you're fixing a typo, adding a new research paper, suggesting a tool, or submitting code, your contributions help build a better, safer AI resource ecosystem.

## Choose Your Contribution Path

We welcome contributions from everyone—no matter your experience level! Choose the pathway that works best for you:

### Track A: Contribute via Discord (Beginner-Friendly)
If you aren't familiar with Git, terminal commands, or GitHub Pull Requests, you can still contribute!

1. **Join the Discord:** [Insert Your Discord Invite Link Here]
2. **Post Your Resource:** Head to the `#resource-submissions` channel.
3. **Drop Your Submission:** Share paper links, AI tools, or fix broken links.
4. **Credit:** A maintainer will format your submission and credit you in the release notes!

---

### Track B: Contribute via GitHub (Experienced Contributors)

If you are comfortable using GitHub, follow our standard issue-and-PR workflow:

#### 1. Pick an Issue
Browse the **Issues** tab on our repository. Look for colorful **Labels (Tags)**:
* `good first issue` – Quick, straightforward tasks for newcomers.
* `documentation` – Updating Markdown files, fixing links, or writing summaries.
* `enhancement` – Adding new features, subfiles, or structural improvements.
* `bug` – Fixing broken code, scripts, or rendering issues.

> Leave a comment on the issue saying *"I'd like to work on this!"* so a maintainer can assign it to you.

#### 2. Pull Request (PR) Workflow
1. **Fork** this repository to your own account.
2. **Clone** your fork locally and create a new feature branch:
   ```bash
   git checkout -b docs/add-new-benchmark
3. **Commit** your changes with clear, short messages:
   ```bash
   git commit -m "docs: add Inspect framework to tools/evaluation.md"
4. **Push** to the fork and submit a **Pull Request (PR)** targeting our main branch.
5. Reference any related issues in your PR description.

## Security & Disclosure Policy

Security is a core focus of this project. Please adhere to these safety practices:

### Responsible Disclosure
* **DO NOT** open a public GitHub issue or post in public Discord channels if you discover a security vulnerability or exploit in our infrastructure/codebase.
* **DO** report vulnerabilities privately via **GitHub Private Vulnerability Reporting** (under the `Security` tab) or DM a maintainer on Discord.

### Code & Content Safety Guidelines
* **No Secrets:** Never commit API keys, tokens, or private credentials. Use `.env` files for local testing.
* **Verify Links:** Ensure external links point to official publishers, arXiv preprints, or trusted open-source repositories.
* **Quality Over Quantity:** Avoid submitting low-quality, unverified, or purely AI-generated text ("slop") without human review.
